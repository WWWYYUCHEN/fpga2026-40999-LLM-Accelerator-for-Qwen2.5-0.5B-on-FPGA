# 原生测试向量实板复测

结论：独立 Win32 接收器与可见窗口已验证，自动启动现已实测到 READY，持续采集 TX=0。完整成功链路为 FSBL 2020.2 / U-Boot 2020.01 → SD /boot.scr → PL → QWUART.ELF → 分词自检 → 模型加载 → READY。此前 U-Boot 2022.01 路径曾报 SD 探测失败 -110；不能将该问题描述为当前仍未解决的启动阻塞。旧监听器是否因休眠或其他原因异常，不能仅凭新接收成功反向证明；其接收健康验收证据确实不足。

| 检查项 | 实际证据 |
| --- | --- |
| 原监听 | 曾跨电脑休眠；仅有进程状态，不足以验证句柄和接收循环 |
| 原日志修正 | 旧 uart-live.log 后续出现 U+FFFD 替换字符，不能再描述为始终没有数据；原始字节未保留，无法恢复该字符对应的线缆数据 |
| 独立接收 | `../tools/kv260_uart_native.py` 使用 Win32 API，无 .NET SerialPort / pyserial 依赖 |
| 有限诊断 | COM11 原生接口打开成功，12 秒内收到 0 字节，未报告 UART 错误；在 3 秒静默后发送过一次 CR 请求空闲提示符，无返回 |
| 启动输出 | 原生持续接收器已抓到 FSBL 2022.2、U-Boot 2022.01；自动倒计时正常到 0，TX=0 |
| 曾观察到的阻塞 | U-Boot 2022.01：Sdhci card detect state not stable；probe failed: -110；no mmc device at slot 1；回退网络/PXE |
| 最终自动启动结果 | U-Boot 2020.01：SD 可识别，自动执行新脚本，PL configured，候选应用启动并进入 READY |
| 诊断边界 | 不推断 -110 具体物理原因，不宣称两种引导版本都稳定；完整断电冷启动重复未独立验收 |
| 可见窗口 | 通过 EnumWindows / IsWindowVisible 确认标题 KV260 COM11 native UART 的窗口可见，不再只依据 Start-Process 成功 |
| 当前配置回读 | 115200、8 数据位、无校验、1 停止位、flags=1（仅 fBinary；DTR/RTS 与软硬件流控关闭） |
| 当前持续接收 | 每 2 秒更新 PC 上的 JSON 心跳，保存 raw bytes；启动时 probe_enter=false，不发送命令或打断倒计时 |

文件：

- native-com11-diagnostic.log / .json：12 秒有限诊断证据，包含一次 CR 的明确记录。
- native-live.log：新持续接收器显示日志，非法 UTF-8 用字节转义呈现。
- native-live.json：当前 PID、配置回读、心跳、接收/发送字节数和 UART 错误。

验收已完成：自动执行新脚本并进入 READY，固定证据见 automatic-boot-to-ready.log / automatic-boot-verification.json。本轮接收器记录到 BREAK / FRAME，启动文本整体可读；这些标志本身不作为最终故障原因。诊断未改 boot.scr、固件、模型、RTL 或 QSPI，未运行推理；全部诊断文件已集成在本目录。
