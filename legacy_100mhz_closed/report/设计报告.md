# Qwen2.5-0.5B KV260 加速推理系统设计报告

## 1. 项目概述

本项目面向 AMD Kria KV260，实现 Qwen2.5-0.5B-Instruct 的 PS 裸机控制与 PL 加速推理。系统采用 INT8 权重、BF16 激活、FP32 累加和 BF16 输出，通过 USB UART 提供交互式文本生成。

核心目标是在单块 Kria K26 SOM 上完成从 SD 启动、PL 配置、模型加载、Tokenizer、Transformer 推理到 UART 输出的完整链路。

## 2. 系统架构

### 2.1 模型

| 项目 | 参数 |
| --- | ---: |
| Transformer 层数 | 24 |
| Hidden size | 896 |
| Q attention heads | 14 |
| KV heads | 2 |
| Head dimension | 64 |
| MLP width | 4864 |
| Vocabulary size | 151936 |
| 总参数 | 494,032,768 |

### 2.2 数据通路

- 权重以 INT8 存储在 SD 卡，并由 PS 加载到内存。
- 输入激活和归一化中间量使用 BF16。
- 矩阵累加使用 FP32，层输出转换回 BF16。
- Embedding 与 LM Head 共享参数。
- PL 通过 AXI-Lite 接收 PS 控制命令，通过 AXI 数据通路访问权重和中间缓冲。

### 2.3 PS/PL 分工

PS 裸机程序负责：

- SD 卡和模型资源加载。
- UTF-8 输入、Tokenizer、聊天模板和上下文管理。
- Embedding 准备、AXI-Lite 寄存器配置和完成状态轮询。
- Token 解码、UART 输出和结果日志。

PL 加速器负责：

- 24 层 Transformer 的矩阵乘、归一化、RoPE、Attention 和 MLP。
- 参数 RAM、KV 缓存和结果寄存器。
- 每次推理的分层调度和完成事件。

## 3. 硬件实现

| 项目 | 结果 |
| --- | --- |
| 目标时钟 | 100 MHz |
| Setup WNS | +1.700 ns |
| Hold WHS | +0.010 ns |
| Bitstream | `build/hardware/qwen25_system_100mhz.bit` |
| XSA | `build/hardware/qwen25_system_100mhz.xsa` |
| SD PL 镜像 | `board/deployment/QWEN25.BIN` |
| PS 固件 | `board/deployment/QWUART.ELF` |

bitstream、XSA 和 SD 启动镜像来自同一实现基线。PL0 在启动阶段配置，PS 固件随后加载模型资源并进入交互循环。

## 4. 启动与交互

启动链：

```text
QSPI → FSBL 2020.2 → U-Boot 2020.01
→ /boot.scr → QWEN25.BIN → QWUART.ELF
→ 模型加载 → TOKENIZER_SELFTEST_OK
→ READY / prompt>
```

UART 参数为 `115200 8N1`、无流控。支持的命令：

| 命令 | 作用 |
| --- | --- |
| `/template chat` | 使用 Qwen 对话模板 |
| `/template raw` | 使用原始 Token 输入 |
| `/mode text` | 输出可读文本 |
| `/mode ids` | 输出 Token ID 和计时 |
| `/mode events` | 输出 Token ID、UTF-8 字节和计时 |
| `/max N` | 设置生成上限，范围 1–255 |
| `/reset` | 清空当前推理上下文 |
| `/selftest` | 执行 Tokenizer 自检 |

当前集成交互固件的 KV 容量为 256 token。每个问题单独开始，不保留跨请求对话历史。

## 5. 验证结果

### 5.1 仿真与数值

- 6 类系统回归场景全部 PASS。
- 每个输出 Token 检查 24 层完成事件、151936 个 logits、argmax 和 CSR 状态。
- 单 Token prefill 的逐层最大相对 L2 误差为 `0.00044046511`。
- 最终归一化 896 元素的相对 L2 误差为 `0`。
- LM Head 相对 L2 误差为 `3.3777615e-05`。

最终场景结果位于 `sim/reports/system_regression/final_*`。

### 5.2 上板功能

KV260 实板完成 6 类场景、7 次请求和 22 个输出 Token，Token ID、UTF-8 字节、输出数量、结束原因和应用状态全部与参考一致。

| 场景 | 模板 | 输入 | 输出 Token |
| --- | --- | --- | --- |
| final_all_layers | raw | 你好 | `3837, 35946` |
| final_rows9_prefill | raw | 123456789 | `16` |
| final_chat_nihao | chat | 你好 | `108386, 6313, 112169, 102804, 47874, 1773, 104139, 109944` |
| final_chat_eos | chat | 1+1等于几？ | `16, 10, 16, 107106, 17, 1773, 151645` |

### 5.3 板内性能

| 场景 | 首输出窗口 / ms | Decode 平均 / ms |
| --- | ---: | ---: |
| raw 你好 | 134.571 | 136.986 |
| 9-token prefill | 522.898 | — |
| chat 你好 | 1675.433 | 240.591 |
| chat 1+1等于几？ | 2074.512 | 255.404 |

Decode 长度扫描使用 prompt 1、10、20、30 token 四档数据，共 28 个有效 decode 样本：

```text
T_ms = 133.680537 + 3.244886 × n_history
R² = 0.99994161
RMSE = 0.273527 ms
```

上述计时由 PS `XTime` 包围 PL START 至 DONE 窗口，不包含分词、Embedding 拷贝、UART 输出和 SD 日志写入。

## 6. 复现

1. 将 `board/deployment/` 全部复制到 FAT32 SD 卡根目录。
2. 插入 SD 卡并连接 USB UART。
3. 上电，等待自动进入 `READY / prompt>`。
4. 运行 `/selftest` 后开始输入。

仿真入口：

```powershell
python .\src\PC\run_cli.py
python .\src\PC\run_cli.py --prompt "你好" --tokens 8
```

完整结果汇总见 `../data/测试结果汇总.csv`，原始串口记录和逐场景数据位于 `../board/measurements/`。

## 7. 说明

当前提交版本以已验证的 256-token 交互固件为准。16K 为设计目标与缓存规划参数，不等同于当前固件开放容量。板内计时是推理计算窗口，不是用户端到端吞吐。
