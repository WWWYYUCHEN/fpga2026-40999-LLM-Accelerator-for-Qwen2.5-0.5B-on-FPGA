# 技能包与协作方法

本项目沉淀的可复用方法：

- **先量化再谈收益**：KV8 量化把 KV-cache 从 BF16 压到 8 bit 分组，但必须逐层核对 clip 与
  sticky 位（`KV8_CLIP` 日志），否则误差以不易察觉的方式累积。
- **厂商 IP 与自研路径要能互相验证**：EXP/ADD 用 `tb_exp_compare.vhd`、`tb_add_compare.vhd`
  与行为级模型对照，避免"IP 配置对了但延迟假设错了"。
- **仿真、综合、上板三套口径分开记录**：本分支只有仿真与时序，就明确写"没有上板数据"，
  不把仿真结果当实测。
- **构建必须可复现**：脚本强制新 `-Tag`、拒绝覆盖已存在的对象目录，避免"跑出来的是上一次的产物"。
- **重复文件会污染交付**：原始交付里同名文件存在 `(1)`/`(2)` 副本（1.65 GB），入库前必须去重。
- **证据链用哈希闭环**：logits 存原始二进制 + SHA-256，token 序列存 CSV，任何人可重算。

数据与结论的对应关系见 `data/README.md` 与 `sim/candidate9_chat_result/`。
